# 1. Audio lives on Hugging Face and GitHub Releases, not in git

Date: 2026-08-25

The archive is about 500,000 MP3 files and 102 GB. Git cannot carry that usefully, and GitHub's limits (100 MB per file, repositories expected to stay under a few GB) rule it out outright. Git LFS would work technically but costs money at this scale and gives no per-file URL. So the repository holds everything that is small and verifiable, and the audio is published twice: on Hugging Face as one dataset per set (each set is about 6,350 files, which respects the Hub's hard limit of 10,000 entries per folder and its recommendation of fewer than 100,000 files per repository), and on GitHub Releases as one release per set with one zip per surah (each far below the 2 GiB per-asset limit, at most 118 assets against the 1,000 allowed per release). Two homes because they fail differently: Hugging Face gives per-ayah URLs and library integration; GitHub Releases gives whole-surah bundles that survive if the Hub changes its storage policy for public datasets, which it has done before. The per-file manifests in git make any copy from either home verifiable. Rejected: a single Hugging Face repository (five times over the file-count guidance), the Internet Archive as primary (slow, no per-file API worth building on), Cloudflare R2 (recurring cost, one more account).
